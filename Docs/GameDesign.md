# Incremental Defense 게임 기획서

> 수치는 별도 표기가 없으면 밸런싱 시작값이며 플레이테스트로 조정한다.
> 제안 또는 가정에 해당하는 내용은 [12. 미정 항목](#12-미정-항목)에 모아 두었다.

## 1. 개요

| 항목 | 내용 |
| --- | --- |
| 장르 | 인크리멘탈 + 디펜스 (로그라이트형 환생 구조) |
| 시점 | 2D 스프라이트 기반 2.5D 사이드뷰 |
| 플랫폼 | PC 우선 (Windows/Steam, 마우스 UI) |
| 엔진 | Unity 6000.6, ECS (Entities) |
| 플레이 시간 | 런 1회당 10~30분, 액티브 플레이 |
| 핵심 재미 | 수만 마리의 적을 포탑으로 쓸어 내고, 런을 거듭할수록 강해지는 성장 |

## 2. 핵심 루프

```
자원 채취 → 포탑 설치 → 적 처치 → 돈·경험치 획득
    ↑                                  │
    └── 채취 장치·포탑 강화, 테크 노드 해금 ──┘

기지 파괴 또는 자발적 포기 → 환생 포인트 획득 → 영구 강화 → 새 런
```

## 3. 플레이어와 맵

- 플레이어 캐릭터는 없다. **마우스 커서로 설치, 강화, 해금**을 수행한다.
- 맵의 구성: `적 출현 지점 → 길목 → 기지 → 기지 뒤 자원 채취 구역`
- 길목은 좌우로 긴 **깊이 있는 띠** 형태다. 위아래 폭이 있어 무리가 넓게 퍼지며, Y값으로 렌더 순서를 정해 2.5D 느낌을 낸다.
- 첫 개발 범위의 길목은 **1개**다. 추후 맵마다 지형과 길목 구조가 다르도록 확장한다.
- 맵 구조를 데이터로 분리해 두어 길목 확장에 대비한다.

## 4. 전투

### 포탑

- 길목 주변의 **정해진 슬롯**에만 설치한다. 슬롯은 제한되어 있어 무엇을 놓을지 선택해야 한다.
- 설치 비용은 **자원**이다.
- 같은 종류를 설치할수록 그 종류의 비용이 오른다.
  - `설치 비용 = 기본 비용 × 1.2 ^ (해당 종류의 현재 설치 수)`
- 설치한 포탑은 **약 70% 환급**을 받고 판매할 수 있다. 판매하면 해당 종류의 설치 수가 줄어 비용도 함께 내려간다.
- 강화는 슬롯 개별이 아니라 **종류별 일괄**로 적용한다.
- 포탑은 적의 공격을 받지 않는다.

### 웨이브와 적

- 웨이브는 **타이머로 자동 진행**한다. 남은 적이 있어도 다음 웨이브가 출발하므로, 화력이 부족하면 적이 쌓여 자연스럽게 무너진다.
- 동시 표시 목표는 **적 1만~5만 마리**다.
- 적은 길목을 따라 기지로 이동해 기지를 공격한다.
- 웨이브는 무한하며 적의 강함은 지수적으로 증가한다. 어떤 런이든 언젠가는 끝난다.
- 특정 웨이브에 **보스**가 등장하는 마일스톤이 있고, 최초 처치 시 새 콘텐츠를 해금한다.

### 패배

- **기지 HP가 0**이 되면 런이 종료된다.
- 플레이어는 언제든 **자발적으로 환생**해 현재 기준의 포인트를 받을 수 있다.

## 5. 재화와 성장 축

| 구분 | 획득 | 사용처 | 환생 시 |
| --- | --- | --- | --- |
| 자원 | 기지 뒤 채취 | 포탑 설치 | 초기화 |
| 돈 | 적 처치 | 채취 장치 강화, 포탑 종류별 강화 | 초기화 |
| 경험치 | 적 처치 | 레벨 상승 | 초기화 |
| 테크 포인트 | 레벨 상승 | 테크 노드 해금 | 초기화 |
| 환생 포인트 | 런 종료 | 영구 강화 | 유지 |

### 자원 채취

- 런 초반에는 **클릭**으로 직접 캔다.
- 돈으로 **자동 채취 장치**를 구매하고 강화한다. 장치의 생산량과 개수가 인크리멘탈 성장의 중심이다.

### 테크트리

- 레벨이 오르면 **테크 포인트**를 얻고, 이 포인트로 노드를 해금한다.
- 노드에는 새 포탑, 특수 효과, **특정 종류 포탑의 강화**가 들어간다.
- 런 안에서만 유효하며 환생하면 초기화된다. 런마다 다른 빌드를 선택하게 만드는 역할이다.

## 6. 환생

- 환생 포인트는 **세 지표의 곱 연동**으로 계산한다.
  - `포인트 = (버틴 시간 점수 + 처치 수 점수) × 채취 투자 배율`
  - 채취 투자는 배율로만 작용하므로, 전투를 포기하고 채취에만 투자하면 점수가 나오지 않는다.
  - 인크리멘탈 특성상 각 항목에는 로그나 거듭제곱 보정을 적용해 포인트 폭증을 막는다.
- 환생 포인트로 런을 넘어 유지되는 **영구 강화**를 구매한다.

## 7. 템포

- 런은 10~30분의 액티브 플레이를 기준으로 설계한다.
- 런 중에는 **배속**을 제공한다.
- **오프라인 진행은 없다.**

## 8. 게임 목표

- 웨이브는 무한하고 기록 갱신이 기본 목표다.
- 보스 마일스톤이 중간 목표와 콘텐츠 해금의 역할을 맡는다.

## 9. 기술 방향

프로젝트에는 Unity 6000.6, Entities 6.6, Entities Graphics 6.6, URP 17.6, Cinemachine, Feel이 설치되어 있다.

| 영역 | 방향 |
| --- | --- |
| 적 시뮬레이션 | ECS + Burst + Job으로 이동, 피격, 사망 처리 |
| 적 렌더링 | 쿼드 + GPU 인스턴싱 + 스프라이트 시트 셰이더로 직접 그림 |
| 2.5D 표현 | Y값 기반 정렬, 깊이 띠 안에서 위치 분산 |
| 타겟팅 | 공간 분할(그리드/해시)로 범위 탐색 |
| 큰 수 | 지수 성장에 대비한 수치 타입과 표기법 사용 |
| UI, 연출 | GameObject 쪽에서 처리, ECS와 이벤트/싱글턴으로 연결 |

- Entities Graphics는 2D 스프라이트 지원이 제한적이므로, 렌더링 방식을 첫 기술 검증 항목으로 삼는다.
- Feel은 MonoBehaviour 기반이므로 UI, 카메라, 보스 등장 같은 연출에만 사용한다. 개별 적에게는 붙이지 않는다.

## 10. 첫 플레이 가능 빌드 (MVP)

| 항목 | 범위 |
| --- | --- |
| 맵 | 길목 1개 |
| 포탑 3종 | 단일 대상, 범위, 지연 |
| 적 3종 | 일반, 빠름, 탱커 |
| 보스 | 1종 |
| 시스템 | 채취, 설치와 판매, 웨이브, 돈 강화, 테크트리, 환생과 영구 강화 |

## 11. 검증 목표

1. PC에서 적 1만~5만 마리를 목표 프레임으로 시뮬레이션하고 렌더링할 수 있는가
2. 채취, 전투, 강화의 순환이 런 10~30분 안에 잘 돌아가는가
3. 환생을 반복할수록 이전보다 멀리 가는 성장이 느껴지는가
4. 비용 증가와 슬롯 제한으로 포탑을 섞는 선택이 실제로 생기는가
